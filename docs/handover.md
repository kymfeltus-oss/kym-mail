# Engineering handover

KYM Mail contains the Gate 1 foundation through Gate 5 Job Search, the Gate 6 authoritative Master Career Profile, Gate 7 Career Match, and Gate 8 Tailored Resume Engine. It is a Next.js/React/TypeScript application with real Supabase authentication and RLS, unified mail, contextual Projects, deterministic scheduling, vendor-neutral job discovery, normalized Saved Jobs, structured source-backed career facts with field provenance, persisted evidence-linked job analyses, and validated versioned resume exports.

## Ownership and service relationships

The canonical source repository is `https://github.com/kymfeltus-oss/kym-mail`, and this project directory is its root. KYM Mail is intentionally isolated from the unrelated parent `Identification-Engine` repository and its history. Production is `https://www.kymmailapp.com` in the Vercel project `kym-mail`. Persistence and owner authentication use Supabase project `wrmemvvzdxxzwstnjcau`. Gmail OAuth, Gmail API, and Pub/Sub resources use Google Cloud project `kym-mail`.

Vercel and local development receive secrets only through environment stores. Do not put secret values, `.env` files, downloaded OAuth credential JSON, screenshots containing credentials, Supabase service-role keys, OAuth state secrets, or token-encryption keys in Git, documentation, support output, or application logs. Rotate any credential immediately if it is displayed or shared outside its intended secret store.

Major directories: `src/app` owns routes and server actions; `src/components` owns shared presentation; `src/domain` owns vendor-neutral contracts; `src/lib` owns auth, Supabase access, environment handling, errors, and logging; `supabase/migrations` owns schema history; `docs` explains operations and architectural law.

Follow the README to run, test, and build. Deployment is standard Vercel plus independently managed Supabase migrations. Runtime dependencies are Next.js, React, Supabase SSR/client, Zod, Lucide icons, `docx`, and `pdfkit`. Tailwind and quality tooling are development dependencies.

KYM Mail records multiple owner mail identities. `kym@kymmailapp.com` is the default professional/direct sender and `info@kymmailapp.com` is the general/business sender. They use the owner-controlled production domain because `kym.com` was unavailable. They are identities within one unified mailbox experience, not separate apps or authentication users. This mail-identity change does not by itself change the private owner's Supabase authentication email.

Gate 3 uses one Project table with five validated types and four persisted statuses. Project type is intentionally immutable in V1. Parameters are explicit versioned Zod contracts persisted as JSONB; they are not a generic extension bucket. The owner-facing delete policy is Archive/Restore. The default sender references a real mail identity; if it becomes unavailable, the Project remains readable and Compose requires an explicit usable sender instead of silently falling back. Ordinary global mail remains available with no Project.

Gate 4 uses one relational scheduled-message snapshot, private Supabase Storage attachments, an explicit five-state machine, service-role-only atomic claim/recovery functions, and a protected one-minute Vercel Cron executor. It sends through the existing Google provider, preserves the selected identity and Project, synchronizes successful messages into ordinary Sent/threads, and prevents double sends with conditional state transitions plus a deterministic RFC Message-ID. Edit/reschedule/cancel operate only before claim; cancellation is retained and idempotent. See `docs/deployment.md` for recovery and cron operations.

Gate 5 uses the Adzuna standard Job Search API behind `JobSearchProvider`. Search is global, deterministic, and never AI-generated. Job Search Project parameters can pre-populate supported controls but remain editable. Search results are normalized, safely rendered, deduplicated, and source-attributed; they are not persisted until Save. The server re-verifies the provider result before creating/updating one authoritative `job_opportunities` row. A saved opportunity may associate with multiple active Job Search Projects without duplication. The only lifecycle states are Saved and Archived. Provider descriptions are snippets; original postings remain authoritative.

Gate 6 uses migration `202608240010_master_career_profile.sql` and the generic `career:import` administrative command. It retains canonical organizations, titles, experiences, clients, education, credential status, categorized skills, projects, accomplishments, quantified metrics, aliases, and field-level provenance. The currently approved import contains eleven employment records, including three explicitly partial earlier-employer records with no inferred dates/titles, and one canonical ASC606 Revenue Engine project with the ASC 606 Audit Automation alias. Authenticated product access is read-only; service-role ingestion is isolated and authority guarded. The original PDFs and temporary intake file are deliberately not committed.

Gate 7 uses migrations `202608240011_job_intelligence.sql` and `202608240012_job_intelligence_partial_gaps.sql`. Saved-job analysis extracts structured requirements from the complete available description, matches them to Gate 6 evidence, calculates a deterministic weighted score, and persists requirement/evidence rows. The correction migration permits a truthful structured gap on a partial match, such as CPA Candidate versus an active CPA license. Re-analysis does not mark the last `COMPLETE` analysis stale until the new result is ready to complete; a failed attempt leaves the prior success recoverable.

Gate 8 uses migration `202608250013_tailored_resume_engine.sql`. A persisted deterministic resume plan promotes Gate 7 positive/partial evidence while the Gate 6 profile remains the only factual authority. The provider boundary returns Zod-validated structured content; the currently configured provider is the legitimate deterministic fallback (`deterministic-gate8-v1`), not an AI model. Employment, client relationships, titles, dates, education, credential status, skill/project identities, evidence links, and numeric claims are validated before a version can become current. User edits and full/section/bullet regenerations create child versions. Failed attempts preserve the last successful version, while changes to the job, analysis, or career profile make prior versions `STALE`. ATS-oriented web preview, DOCX, and selectable-text PDF share one content snapshot and section order.

Intentionally deferred from Gate 8: cover-letter generation, hiring-manager discovery, outreach email generation, automatic applications, interview coaching, additional mail/job providers, saved-search monitoring, and a general LLM provider. The locked future career-outreach architecture is maintained in `docs/future-career-outreach-workflow.md`.
