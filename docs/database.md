# Database

Supabase-managed PostgreSQL is the database. Migrations in `supabase/migrations` are the only schema change mechanism and run in filename order.

Gate 1 established `public.profiles` and owner-scoped `public.mail_accounts`. Gate 2 adds `mail_connections`, the server-only `mail_connection_credentials`, unified `mail_threads`, `mail_messages`, attachment metadata, and deduplicated provider notifications. A connection is distinct from a sending identity: both configured addresses link to the same Google mailbox connection. Provider IDs are unique within that connection, and each thread/message retains the relevant account identity.

Migration `202608240007_projects.sql` is the authoritative Gate 3 schema. It adds one `projects` table, `project_activity`, and nullable `project_id` foreign keys on existing threads/messages. Project types are `JOB_SEARCH`, `BUSINESS_OUTREACH`, `PARTNERSHIP`, `NETWORKING`, and `CUSTOM`; statuses are `ACTIVE`, `PAUSED`, `COMPLETED`, and `ARCHIVED`. The default identity is a relational foreign key to `mail_accounts` with `ON DELETE SET NULL`, so an unavailable or removed identity never invalidates the Project or causes silent sender substitution.

Type-specific parameters are versioned JSONB objects (`parameter_schema_version = 1`) whose explicit per-type Zod schemas are authoritative at the server boundary. The database constrains the container shape and owner relationships; JSONB does not hold normalized mail, contact, job, resume, or identity records. Owner-consistency triggers prevent cross-owner Project/account/thread/message associations. RLS restricts Projects to the authenticated owner and exposes Project Activity as owner-readable but trigger-written. Anonymous access has no policy. Archive is the normal deletion policy; there is no owner-facing permanent-delete route.

Migration `202608240008_scheduled_mail.sql` is the authoritative Gate 4 schema. `scheduled_messages` stores typed delivery state and the exact approved mail snapshot; `scheduled_message_attachments` stores private object metadata and SHA-256 integrity values; `scheduled_message_events` stores deterministic schedule activity. Status is the `scheduled_mail_status` enum: `SCHEDULED`, `PROCESSING`, `SENT`, `FAILED`, or `CANCELLED`. Database checks require valid cardinalities, state-dependent claim/provider fields, and owner-consistent account/Project/attachment relationships.

`claim_due_scheduled_messages()` performs the only delivery claim transition with a row lock and `SKIP LOCKED`, so overlapping invocations cannot claim the same row. `recover_stale_scheduled_messages()` releases abandoned claims after ten minutes or fails them at the attempt limit. Both functions are revoked from public, anonymous, and authenticated roles and executable only by `service_role`. Owner RLS is read-only at the tables; mutations flow through authenticated, same-origin server routes that re-resolve the owner and conditionally update status/version. The private Storage bucket has no client policies and a 10 MB per-object limit.

Migration `202608240009_job_search.sql` is the Gate 5 schema. `job_opportunities` persists only validated normalized fields and narrow reconciliation/provenance metadata; it does not store the raw Adzuna response. The unique owner/provider/provider-job key makes repeated Save idempotent, while a unique owner/source-URL index catches provider duplicates with changing identifiers. Status is deliberately limited to `SAVED` and `ARCHIVED`.

`job_opportunity_projects` is the normalized many-to-many relationship between one authoritative opportunity and active Job Search Projects. A database trigger verifies that the opportunity and Project share an owner, that the Project is `JOB_SEARCH`, and that it is not archived. `job_project_activity` records association/removal events for the Project workspace. All three tables use owner-only RLS; anonymous access has no policy. Source/application URLs must be HTTPS, descriptions are bounded plain text, salary ranges are internally consistent, and employment/work-arrangement values are constrained.
